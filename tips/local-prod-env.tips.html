Step 1 of 6

1. 실행하기 (매번)

알려는 것: 개발 서버를 켜고 https://local.prettylog.com을 여는 법. 운영 Clerk 키는 앱의 env 파일에 이미 있다. 키를 입력하는 단계가 없다.

저장소 루트(또는 worktree 루트)에서
LOG_REQUESTS=false NEXT_PUBLIC_API_BASE=https://blog-api.prettylog.com \
pnpm --filter dashboard_client_web exec next dev --turbopack -p 443 -H 0.0.0.0 --experimental-https \
  --experimental-https-key "$HOME/.config/prettylog/certs/local-key.pem" \
  --experimental-https-cert "$HOME/.config/prettylog/certs/local.pem"
  • 브라우저에서 https://local.prettylog.com을 연다. 포트는 붙이지 않는다.
  • 끌 때는 Ctrl+C를 누른다.
  • LOG_REQUESTS=false는 요청 로그 한 줄씩을 끈다.
하고 싶은 일어떻게
운영 데이터로 보기와 로그인위 명령 그대로
프로젝트 그룹 mock 화면 보기명령 맨 앞에 PROJECTS_DATA_SOURCE=mock을 붙인다
포트 443을 누가 쓰는지 확인lsof -iTCP:443 -sTCP:LISTEN
mock 프로젝트 그룹 (Phase PG M1)
PROJECTS_DATA_SOURCE=mock LOG_REQUESTS=false NEXT_PUBLIC_API_BASE=https://blog-api.prettylog.com \
pnpm --filter dashboard_client_web exec next dev --turbopack -p 443 -H 0.0.0.0 --experimental-https \
  --experimental-https-key "$HOME/.config/prettylog/certs/local-key.pem" \
  --experimental-https-cert "$HOME/.config/prettylog/certs/local.pem"
  • 열기: https://local.prettylog.com/@taeklim/projects
  • 열기: https://local.prettylog.com/@taeklim/projects/mock-utrgv-project
  • 값이 정확히 mock일 때만 mock이다. 변수를 빼면 실제 데이터가 나온다.
  • 서버 전용 변수다. NEXT_PUBLIC_ 접두가 없다.
  • 이 변수는 브랜치 pg-m1에 있다 (PG-1-03). main에 머지되기 전에는 그 브랜치에서만 동작한다.
git worktree에서 실행할 때: env 파일 연결 (worktree마다 한 번)

worktree는 저장소 바깥에 만든다 (예: ../project_tradelunch_pg). worktree에는 env 파일과 @repo/types의 빌드 결과(dist/)가 없다. 그래서 아래 세 단계를 한 번 한다. 빌드를 빼면 페이지가 500이다 (Can't resolve '@repo/types'). env 파일은 메인 저장소의 파일을 심볼릭 링크(symlink)로 건다. <main>은 메인 저장소 경로, <worktree>는 worktree 경로다.

pnpm install --offline --frozen-lockfile
pnpm --filter @repo/types build
for f in .env .env.local .env.production; do
  ln -s <main>/apps/dashboard_client_web/$f <worktree>/apps/dashboard_client_web/$f
done
포트 443은 서버 하나만 쓴다
  • 다른 서버가 443을 잡고 있으면 새 서버가 뜨지 않는다.
  • lsof -iTCP:443 -sTCP:LISTEN으로 찾고, 그 서버를 Ctrl+C로 먼저 끈다.
Step 2 of 6

2. 어떻게 연결되나

알려는 것: 로컬 웹은 운영 DB에 직접 붙지 않는다. 운영 API(https://blog-api.prettylog.com)를 부르고, 그 API가 운영 Supabase DB를 읽는다. 로컬에서 도는 것은 Next 서버뿐이다.

로컬 웹이 운영 API를 부르는 길. 왜: 개발 키로 만든 토큰은 운영 API가 받지 않아 401이 난다.

부품하는 일왜 필요한가
/etc/hostslocal.prettylog.com을 127.0.0.1로 보낸다Clerk 운영 키는 prettylog.com 하위 도메인에서만 동작한다
포트 443origin에서 포트를 없앤다https://local.prettylog.com:3000은 Clerk가 거부했다 (2026-10-13)
-H 0.0.0.0모든 주소에서 받는다macOS는 1024 미만 포트를 0.0.0.0에서만 일반 사용자에게 열어 준다. 127.0.0.1:443은 EACCES가 난다
mkcert 인증서Mac 전용 인증기관(CA)이 local.prettylog.com용 인증서에 서명한다Clerk 쿠키는 Secure라 HTTPS가 필요하다. Next 기본 인증서는 localhost만 담는다
allowedDevOriginsnext.config.ts가 local.prettylog.com을 허용한다없으면 개발 서버가 그 호스트의 핫 리로드(HMR)를 막는다. 운영 빌드에는 영향이 없다
Step 3 of 6

3. 한 번만 설정

알려는 것: 1단계 명령이 돌기 전에 한 번 해 둘 일. 이미 했으면 건너뛴다.

#할 일어디서언제
a/etc/hosts에 이름 추가Mac한 번
b운영 API에 origin 허용(ALLOWED_ORIGINS)GCP VM한 번
c인증서 만들기Mac한 번, 약 2년마다 다시
a. 이름을 내 Mac으로 보낸다 (Mac)
echo '127.0.0.1 local.prettylog.com' | sudo tee -a /etc/hosts

Cloudflare에 이 이름의 공개 DNS 레코드(또는 * 와일드카드)를 만들지 않는다.

b. 운영 API가 이 origin을 받게 한다 (VM)
grep '^ALLOWED_ORIGINS' ~/prettylog/shared/api.env
# 값은 이래야 한다: ALLOWED_ORIGINS=https://my.prettylog.com,https://local.prettylog.com
vi ~/prettylog/shared/api.env                       # 다르면 고친다
pm2 restart ~/prettylog/ecosystem.config.cjs --only blog-api --update-env
pm2 env $(pm2 id blog-api | tr -dc '0-9') | grep ALLOWED_ORIGINS   # 지금 도는 값
  • 포트, 따옴표, 공백, 끝의 /를 쓰지 않는다.
  • ecosystem 경로는 전체로 쓴다. 짧게 쓰면 ~/prettylog 밖에서 PM2가 못 찾는다.
  • --update-env가 없으면 PM2가 api.env를 다시 읽지 않는다.

Mac에서 확인한다. CORS preflight가 204를 주고 origin을 되돌려 줘야 한다.

curl -s -o /dev/null -D - -X OPTIONS https://blog-api.prettylog.com/v1/api/users/me \
  -H 'Origin: https://local.prettylog.com' -H 'Access-Control-Request-Method: GET' \
  | grep -iE '^HTTP|access-control-allow-origin'
# HTTP/2 204
# access-control-allow-origin: https://local.prettylog.com

헤더 없는 500이면 origin이 도는 값에 아직 없다.

c. 인증서를 만든다 (Mac)

Next가 첫 --experimental-https 실행 때 mkcert를 ~/Library/Caches/mkcert/에 받는다. 폴더가 비었으면 한 번 돌리고 끈다. 이때 Mac 비밀번호를 묻는다.

cd ~/Documents/00_projects/project_tradelunch/apps/dashboard_client_web
ls ~/Library/Caches/mkcert/ 2>/dev/null || pnpm exec next dev -p 3000 --experimental-https   # "Ready"가 뜨면 Ctrl+C

그다음 호스트 이름이 들어간 인증서를 만든다.

MKCERT=$(ls ~/Library/Caches/mkcert/mkcert-* | head -1)
CERTS=~/.config/prettylog/certs
mkdir -p $CERTS
"$MKCERT" -key-file $CERTS/local-key.pem -cert-file $CERTS/local.pem \
  local.prettylog.com localhost 127.0.0.1
chmod 600 $CERTS/local-key.pem
openssl x509 -in $CERTS/local.pem -noout -ext subjectAltName   # DNS:local.prettylog.com이 보여야 한다
  • 인증서는 저장소 밖 ~/.config/prettylog/certs/에 둔다. 실수로 커밋할 수 없고, 새로 clone해도 남는다.
  • 수명은 약 2년이다. 만료되면 같은 명령으로 다시 만든다.
Step 4 of 6

4. 주의: 쓰기는 운영 데이터를 바꾼다

  • 로그인한 상태의 쓰기(댓글, 좋아요, 저장, 글쓰기)는 운영 DB에 실제로 기록된다.
  • 시험 댓글은 공개된다. 끝나면 지운다(soft delete).
  • 0.0.0.0은 같은 네트워크의 다른 기기도 받는다. 시험이 끝나면 Ctrl+C로 끈다.
로그인 없이 읽기만 할 때 (설정 없음)
LOG_REQUESTS=false NEXT_PUBLIC_API_BASE=https://blog-api.prettylog.com pnpm dev:web
# 열기: http://localhost:3000

이 모드는 개발 키를 쓰고 쓰기가 없다. 브라우저가 직접 부르는 호출(더 보기, 좋아요)은 CORS로 실패할 수 있다. 첫 화면(SSR)은 괜찮다.

Step 6 of 6

6. 되돌리기

  • VM의 ALLOWED_ORIGINS에서 https://local.prettylog.com을 빼고 blog-api를 재시작한다.
  • /etc/hosts에서 그 줄을 지운다.
  • Cloudflare에 이 이름의 공개 DNS 레코드를 만들지 않는다.
  • Mac 전용 CA는 Keychain에 남는다. "$MKCERT" -uninstall로 지운다.
